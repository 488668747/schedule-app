# 节奏 · 需求排期

一个面向前端开发者的个人需求排期桌面应用。当前版本支持：

- 按项目查看需求，查看本月排期时间轴
- 新增、编辑、删除需求
- 设置开始日期、结束日期、状态、优先级和图文需求描述
- 富文本支持标题、粗体、斜体、列表、引用、代码块，支持图片上传、截图粘贴和拖入
- 点击需求标题或时间轴查看完整描述，也可从详情进入编辑
- 按项目、状态和关键词筛选
- 数据自动保存在当前设备的 IndexedDB 中，兼容迁移旧版 localStorage 数据
- 导出、导入 JSON 备份，在浏览器与桌面应用、不同设备间手动迁移
- Electron 桌面壳层，可用于 Mac 和 Windows

## 数据保存位置

当前版本不连接服务器，项目、需求和压缩后的图片统一保存在本地 IndexedDB：

- 数据库名称：`rhythm-schedule`，存储区：`state`，数据键：`snapshot`
- 浏览器版：保存在当前浏览器的 `http://127.0.0.1:5173` 站点数据中
- Electron 版：保存在 Electron 的本地用户数据目录中，Mac 通常位于 `~/Library/Application Support/xu-qiu-pai-qi-app/IndexedDB`，Windows 通常位于 `%APPDATA%/xu-qiu-pai-qi-app/IndexedDB`

首次运行会把旧版 `rhythm-schedule-projects-v1` 和 `rhythm-schedule-tasks-v1` 自动迁移到 IndexedDB，保留原有文字备注；旧键保留为迁移时的副本，之后不再更新。请以应用界面及新导出的备份为准，不要用旧副本覆盖最新数据。迁移失败不会用演示数据覆盖旧数据。普通保存和备份导入均在数据库事务提交成功后更新界面。

这些文件是浏览器内部数据库格式，不建议直接编辑；清理站点数据或删除应用用户数据目录会删除数据。应用仍采用本地存储，没有云端自动同步。

## 跨设备迁移与备份

1. 在旧设备左下角点击“数据备份”→“导出 JSON 备份”。导出的是全部项目和需求，包含已完成项、备注、日期、状态和优先级，不受当前筛选影响。
2. 将下载的 `节奏备份-时间.json` 文件通过 AirDrop、网盘或 U 盘等方式传到新设备。
3. 在新设备打开“数据备份”→“选择备份文件”。检查文件名、备份时间和项目/需求数量。
4. 点击“导入并覆盖”，即可替换新设备的全部项目和需求；取消或关闭弹窗不会改动数据。若新设备已有数据，请先导出留档。

支持浏览器版与 Electron 桌面版之间互相导入。新版导出为 v2，包含富文本和全部内嵌图片，文件上限为 50 MB；仍可导入旧版 v1 纯文字备份。新版图文备份需使用新版应用读取。导入前会检查备份格式、版本、日期、项目关联和文档节点，错误文件不会覆盖现有数据。导入采用完整覆盖方式，不会合并两台设备各自的修改；文件是可阅读的 JSON，请妥善保管。

## 图片与存储体积

- 图片支持 PNG、JPEG、WebP，可通过“插入图片”、截图粘贴或拖入添加；选中图片按删除键可移除。
- 原图限制 20 MB，自动转换为 WebP，最长边不超过 1600px，压缩后每张限制 2 MB。缩放后的图片保留在本地，原图不另存；细节很多的长图建议分段截图。
- 图片以数据 URL 内嵌到图文文档，导出时无需另外传图片文件。Base64 编码使压缩图片体积增加约三分之一；文字与格式占用很小，实际增长主要取决于图片数量和大小。
- IndexedDB 容量通常远大于 localStorage，具体配额由浏览器、磁盘空间和运行环境决定。存储不足时会提示保存失败并保留原数据。仍建议定期导出备份。
- 从网页复制描述时保留支持的文字格式；外部图片链接不会自动下载，请上传图片或粘贴截图，以保证离线和跨设备可用。

## 本地运行

建议使用 Node.js 20（项目提供 `.nvmrc`）。

```bash
npm install
npm run dev
```

`npm run web` 可只启动浏览器版，`npm run build` 构建前端，`npm run desktop` 使用构建后的文件启动 Electron。

`npm test` 验证图文备份还原、旧版兼容、文档校验、本地数据迁移和保存失败时的数据保留。

## Mac 安装包

已发布的安装包在 [GitHub Releases](https://github.com/488668747/schedule-app/releases) 下载：打开版本页面，展开 **Assets**，选择 `mac-arm64.dmg`。

```bash
npm run dist:mac
```

在 Mac 上生成与本机芯片对应的 DMG，产物在 `release/Rhythm-0.1.0-mac-arm64.dmg`（Apple 芯片）或 `release/Rhythm-0.1.0-mac-x64.dmg`（Intel）。双击 DMG，把“节奏”拖到 Applications 文件夹即可安装。应用图标已随工程提供；需要重新生成时可在 Mac 上运行 `npm run icons:mac`。

当前安装包使用本地临时签名，未做 Apple 开发者签名和公证。如首次打开被系统拦截，请在“系统设置 → 隐私与安全性”中选择“仍要打开”。

安装版固定使用 `com.dayouzi.schedule-app` 应用标识和 `xu-qiu-pai-qi-app` 用户数据目录，后续版本可在退出应用后覆盖替换 `.app`，正常覆盖不会删除该目录里的数据。浏览器或早期开发版的数据需要先导出备份，再到安装版导入；首次安装不会自动读取浏览器的数据。当前版本需手动安装更新。

安装包不提交到 Git，打包配置和图标源码会同步到仓库。当前仅配置 Mac DMG，Windows 安装包可后续补充。

## 发布新版本到 GitHub

手动发布：在仓库右侧点击 **Releases → Create a new release**，选择或创建与 `package.json` 版本一致的标签（例如 `v0.1.0`），填写中文标题和版本说明，将本地生成的 DMG 拖到附件区，上传完成后点击 **Publish release**。发布后从该版本的 **Assets** 下载。

也可使用本仓库的自动发布流程：更新 `package.json` 和锁文件中的版本号，提交并推送代码，然后创建并推送对应标签：

```bash
git tag -a v0.1.0 -m "发布 v0.1.0 Mac 安装版"
git push origin v0.1.0
```

GitHub **Actions → 发布 Mac 安装包** 会运行测试、构建 Apple 芯片 DMG、检查签名和校验和，再把安装包上传至 Releases。发布说明使用 `docs/releases/mac.md`。以后发布前请修改版本号和说明，并创建一个新的标签；已有版本标签不要移动。若版本存在问题，可在 Releases 编辑页面撤销最新标记或删除该发布，修复后用新的补丁版本重新发布。
